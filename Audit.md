# Project audit and code review

Audit date: 2026-09-09. Target launch: Sunday 2026-09-13, Asia/Kolkata. Scope: current working tree, including existing uncommitted changes. No application fixes or production deployment performed in this audit.

## Release verdict

**Not ready for public launch.** The frontend builds, but private uploads are publicly served, resume updates permit protected-field changes, and several failure paths return fabricated results. Address security and data truthfulness before adding polish. Keep React/Express/MongoDB; a framework rewrite is not justified for this deadline.

This is a source audit with local checks, not a guarantee that every possible vulnerability has been found. Database-backed authorization, browser accessibility, provider behavior, deployed infrastructure, backups and load behavior still require staging verification. Findings distinguish code-confirmed defects from exposure that depends on deployment or external input. No real resumes, private environment values or credentials were copied into these documents.

## Evidence and coverage

- Reviewed all six models, five route groups, five controllers, authentication/upload middleware, database/server initialization, four services, nine frontend pages, seven shared UI components, navigation/auth/API state and build configuration.
- Existing uncommitted application edits were preserved. Existing `test_records.md` contains August claims; they are historical assertions, not fresh September acceptance evidence.
- Production build: **PASS**, Vite 7.2.2, 109 modules, JS 336.76 kB / gzip 102.23 kB; CSS 42.19 kB / gzip 6.63 kB. Initial sandbox denial was an environment failure; authorized rerun succeeded.
- ESLint: **FAIL**, 35 errors and 1 hook-dependency warning across auth context and all nine pages. Errors include explicit `any`, unused caught errors and mixed context/component exports.
- Server package test command is a placeholder that exits 1; no existing automated integration or E2E suite was found.
- Offline probes: [script](docs/audit/reproduce.mjs), [execution output](docs/audit/reproduction-results.txt). These reproduce defects; a successful probe is not a passing product test. Persistence/file deletion are mocked, and no AI/scraper network calls are made by the probes.
- Dependency scan evidence: [server audit](docs/audit/server-npm-audit.json), [client audit](docs/audit/client-npm-audit.json). See [verification report](docs/audit/Verification.md) for completed results and limits.

Source positions below refer to the audited working tree and will move after fixes. P0 = stop public release; P1 = fix before enabling the affected feature; P2 = scheduled improvement. A security severity describes impact; a delivery priority describes when to fix it.

## Architecture recommendations

1. Keep a modular monolith. Split `app` construction from network listen/DB startup so integration tests can create an app without connecting to production.
2. Establish shared request/response schemas and service contracts. Controllers should validate/authenticate/map responses; domain services own business rules; persistence helpers enforce ownership and active state.
3. Make resume content/version the source of truth; text, embeddings and scores are derived from versioned content. Current PUT can change content without recalculating embeddings or preserving prior score meaning.
4. Separate ingestion-cache lifetime from saved application lifetime. Store listing snapshots and analysis provenance. Do not TTL-delete user-visible history.
5. Use private durable object storage or a mounted private persistent volume for the initial single-instance release. Container-local uploads without retention/backups are not a durable platform design.
6. Keep AI operations explicit and bounded. For Sunday, a single validated provider request with clear timeout is simpler than many sequential calls. Jobs require a bounded verified-source implementation and durable worker; hold public release if their gate fails.
7. Add typed frontend feature APIs/hooks and an application shell; avoid a wholesale state-library migration. Extract repeated types and states first. Route-level lazy loading can follow measured need.
8. Add CI for clean install, lint, build, backend tests, dependency audit and core E2E; staging release/rollback proof is a separate gate from compilation.

Owner clarification: **every current feature is mandatory**, including Jobs. Disabling unsafe scraping means containment during development, not omission from public release. Hold release if the module cannot pass. Vercel is the chosen initial hosting platform; see [Deployment.md](Deployment.md).

## Module 1 remediation update — 2026-09-09

The findings above are the original audit snapshot, with original line references. Module 1 changes are now implemented; [local verification](docs/m1/Verification.md) and the [work tracker](Work_Tracker.md) are the current evidence record. No public deployment or project-database migration has occurred.

- S01–S03: the tested mass-assignment/path-deletion/public-active-content chains are contained. M2 retains full storage/lifecycle and format-quality work.
- S04: Multer upgraded to 2.3.0; malformed/oversized/type rejection is tested. Both updated dependency trees report zero npm advisories. Broader aborted-transfer/stress testing remains in the storage gate.
- S05: shared IP/account rate limits, bounded AI requests/slots, provider deadlines and scanner containment implemented. Storage quotas, parsing stress limits and the durable job worker remain later-module work.
- S06–S07: raw account/provider logging removed; opaque HttpOnly sessions, CSRF, expiry, server logout, password/session revocation and hashed one-time recovery are tested locally.
- S08–S09: headers, exact-origin CORS, IDs/query limits, identity validation and safe errors implemented. Complete feature-specific schemas and deployed edge/proxy proof remain open.
- S10: scanner execution is unavailable at the API pending the M5 isolation/network gate. This is containment, not a repaired production scraper.
- S11: full prompt/output/factual-integrity remediation remains M3/M4 work.
- S12: uploads no longer automatically request embeddings and inactive resume access is contained. Complete processing notices, retention, derived-data deletion and backup policy remain open.
- U01–U07: shared input/dialog/navigation/progress/motion controls, identity/settings styling, color variables and page metadata are improved. Browser tests cover the foundation screens. Later feature screens still require their own accessibility/state/design work; unused scaffold CSS is not treated as an active runtime defect.

Do not interpret a clear dependency audit or passing foundation tests as closure of the entire source audit or approval to launch.
